## 1. AGENTS.md commit history

```
8f9ecfe docs: update AGENTS.md with restored health endpoint and Tier C /widgets status code item
6dfb0c2 docs: add pre-commit guardrail to AGENTS.md
```

The stale pytest command was introduced **at creation** in `8f9ecfe`. AGENTS.md was copied from the then-current `ci.yml` which also lacked `tests/scrapers/` (confirmed: `git show 8f9ecfe:.github/workflows/ci.yml | Select-String scrapers` → no output).

When `0791bdd` later added `tests/scrapers/` to `ci.yml`, AGENTS.md was **never updated**. The only subsequent commit (`6dfb0c2`) added the pre-commit guardrail section and did not touch the pytest command.

```diff
   tests/models/ \

+  tests/scrapers/ \
```

Single-line addition. The command had been stale across 12 intervening commits between `0791bdd` (ci.yml fix) and the M14.1 fix.

## 3. Why M12/M13 didn't hit this but M14 did

**M12's own work included the ci.yml fix** — commits `0791bdd` and `60c234e`. The verification report (`m12-cli-fix-and-verification.md`) was specifically about checking that the fixed ci.yml command works. It ran the **ci.yml command, not AGENTS.md**:

- *"Fix applied — reverted all \\ to \ in commit 60c234e. Verified the corrected command produces:"*
- *"Re-ran the full suite (excluding E2E) on the fixed command."*

The "fixed command" refers to the ci.yml content being verified, not the stale AGENTS.md.

**M13's report** (`m13-gap-fill.md`) shows `849 passed`. This is exactly 844 (M12 baseline with scrapers) + 5 (M13's new tests). The report doesn't cite a command source, but the result proves it used the **ci.yml command** (or an equivalent including `tests/scrapers/`). If M13 had used the AGENTS.md command, the count would have been 734 + 5 = 739, not 849.

**M14 used AGENTS.md** because AGENTS.md displays the command under the heading *"(exact CI path — use this to match CI)"* — an explicit instruction for an AI agent to use it as the source of truth. The agent followed that instruction, not knowing AGENTS.md was stale.
